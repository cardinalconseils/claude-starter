# Workflow: Generate Documentation

Five documentation scopes from codebase analysis. Ported from the `doc-generator` agent. Run
by the writer role.

## Inputs

- `scope`: `api` | `arch` | `components` | `onboarding` | `agent` | `all`
- `diff_only`: document only new/changed files
- `project_root`, `CLAUDE.md` (tone, naming, standards), `PRD-PROJECT.md` (overview) when present

## 1. API (`api`)

Detection:

```
Glob: app/api/**/route.{ts,js}          # Next.js App Router
Glob: pages/api/**/*.{ts,js}            # Next.js Pages Router
Grep: "router\.(get|post|put|delete)"   # Express
Grep: "@app\.(get|post|put|delete)"     # FastAPI/Flask
Glob: **/controllers/**/*.{ts,js,py}    # MVC frameworks
Grep: "@(Get|Post|Put|Delete|Patch)"    # NestJS/decorators
```

Per endpoint extract: method and path; request params (path, query, body) from types/schemas;
response schema from return types; auth requirements (middleware, decorators); error
responses; JSDoc/docstring text. Compare against `.kickstart/artifacts/API.md` when it exists
(SKILL.md Step 0).

Output: `docs/api/README.md` (overview, auth guide, base URL), `docs/api/endpoints/{resource}.md`
(one per resource group), `docs/api/openapi.yaml` with `--openapi`
(`references/openapi-template.md`).

## 2. Architecture (`arch`)

Sources: `.prd/codebase/ARCHITECTURE.md` (source of truth when present — translate for
external readers), `CLAUDE.md` stack section, `.kickstart/artifacts/ARCHITECTURE.md`,
directory structure.

Output: `docs/architecture/README.md` (layers, patterns, key abstractions),
`docs/architecture/data-flow.md` (input → processing → storage → output),
`docs/architecture/decisions.md` (ADRs from existing docs and git history). Mermaid or ASCII
diagrams where they help; reference real file paths.

## 3. Components (`components`)

Detection:

```
Glob: src/components/**/*.{tsx,jsx}     # React components
Glob: src/lib/**/*.{ts,js}             # Library modules
Glob: src/services/**/*.{ts,js,py}     # Service layer
Glob: src/utils/**/*.{ts,js,py}        # Utilities
Glob: src/hooks/**/*.{ts,js}           # React hooks
```

Per major module: purpose, exports (public API), dependencies, props/parameters from types,
usage examples from tests. Group related modules — no file per tiny util; public API only.

Output: `docs/components/README.md` (index + dependency graph), `docs/components/{module}.md`.

## 4. Onboarding (`onboarding`)

Sources: `CLAUDE.md`, `README.md`, `package.json`/`pyproject.toml`/`go.mod`, `.env.example`
(keys only, never values), `docs/`.

Output `docs/onboarding.md` with: what the project does; prerequisites; setup (clone, install,
env vars, database); running locally; project structure; key concepts; common tasks; where to
find things.

## 5. Coding-agent context (`agent`)

Produces `./llms.txt` for coding agents — distinct from the marketing `llms.txt` the marketer
maintains for AI search; never overwrite one with the other.

Collision check first: `llms.txt` exists → show it and stop with "llms.txt already exists.
Delete or rename it manually, then re-run." Never overwrite.

Sources with `CLAUDE.md`: one-liner ("What This Project Is"), stack, key paths, critical
conventions (constraints + `.claude/rules/` titles), docs index (`docs/*.md`, `docs/api/`,
`docs/architecture/`), commands (manifest scripts). Without `CLAUDE.md`: stack and commands
from the first manifest found, key paths from the top-level tree, and a leading
`# Note: CLAUDE.md not found — stack detected from manifest`.

Format (terse, ≤40 lines):

```
<!-- Generated by /cks:docs agent — do not edit manually -->
<!-- Last updated: YYYY-MM-DD -->
> Project: {name} — {one-liner}
> Stack: {langs/frameworks@versions}
> Key paths: {dir} ({purpose}), {dir} ({purpose})
> Auth: {critical auth convention if present}
> Critical: {must-not-do rule if present}
> Docs: {docs path}, {docs path}
> Commands: {dev} | {test} | {build}
```

Every path, command, and version must be real. Omit a section rather than write a
placeholder.

## Staleness detection (`all`)

Run all five scopes, then list `docs/api/endpoints/`, verify each documented endpoint still
exists in code, flag docs for removed endpoints or modules, report the stale count.

## Diff mode

`git diff --name-only {last_tag}..HEAD` → keep only API routes, components, and
architecture-affecting files → regenerate docs for those only; leave the rest untouched.

## Output rules

1. Never overwrite a file carrying a `<!-- manual -->` marker
2. Start every generated file with
   `<!-- Generated by /cks:docs — do not edit manually -->` and `<!-- Last updated: YYYY-MM-DD -->`
3. Scannable, not exhaustive
4. Real examples from the project, never generic
5. Link to source paths
6. Never emit secret values
